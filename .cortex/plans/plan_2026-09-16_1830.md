## Architecture Perfection Plan

### Current State
- **Research**: 24 files, ~4,500 lines. Deep and thorough. No gaps that would cause a build failure.
- **Visual architecture**: 5 drawio diagrams covering system overview, data pipeline, security, data model, screens/workflow.
- **Master plan** (`plan.md`): 402 lines. Covers the "why" brilliantly — R1-R6 rules, gates, demo script, testing, schedule.

### The Problem
The architecture is strong on **vision** and **research backing** but weak on **build specifications**. A teammate picking up a component today would still need to ask you questions. The drawio files are visual-only (XML) — no text-readable specs underneath them. Several critical subsystems have no formal specification at all.

### 9 Missing Specifications (ranked by build-blocking severity)

1. **SQL Rule Engine Spec** — How are rules stored? Versioned? Evaluated? What's the exact SQL pattern for each of the 5 gates? `clinical-thresholds.md` has the thresholds but not the engine design.

2. **Cortex Agent Tool Contracts** — plan.md §6 lists 6 tools with 1-line descriptions. Need: exact SQL signatures, input/output types, error states, scope injection mechanism for each.

3. **Answer Validator Spec** — The 5-check pipeline (existence, scope, version, polarity, type match) is described in bullet points. Need: step-by-step flow, what happens on each failure mode, exact AI_FILTER invocation pattern (we now know the syntax is non-obvious).

4. **Document Pipeline Topology** — stage → AI_PARSE_DOCUMENT → extraction → reconciliation is described at a high level. Need: exact task/stream wiring, error handling for parse failures, the extraction prompt template, how reconciliation links assertions to clinical events.

5. **Class A/B Classification Spec** — How does the system distinguish "Is she in danger?" (refused) from "Is she ready for cycle 4?" (answered)? Is it keyword-based? LLM-classified? Rule-based? This is a core architectural decision with no spec.

6. **Cortex Search Service Config** — Dual-corpus design is specified in principle. Need: exact CREATE DDL, attribute columns, refresh strategy, chunk sizing from `snowflake-implementation-patterns.md`.

7. **Semantic View + VQR Spec** — Entities, metrics, time filters, and the 6 pre-verified queries for the demo. This is what makes Cortex Analyst accurate vs. generic.

8. **Synthetic Data Generator Spec** — `data-artifact-map.md` + `should-close-gaps.md` have the pieces but there's no consolidated spec. The 12 corruption scenarios need exact definitions.

9. **Deployment Script Spec** — Git integration pattern from `snowflake-implementation-patterns.md` needs a concrete setup.sql/teardown.sql design.
