## 3. Reconciliation catches a misread that both AI passes agreed on

In the deep case (`PAT-DEEP-0001`), the rotated-photo copy of the 27 Mar 2025 CBC reads platelets **2,60,904**. Both extraction passes agreed, so it was marked `verified`; they read the same OCR text. The clean PDF of the same report reads **2,60,604**, as does the structured record.

The `reconcile_evidence_proc` decisions:

- clean PDF `2,60,604` → **supports** `EVT-CBC-01-PLT`
- photo `2,60,904` → **conflicts with** `EVT-CBC-01-PLT`, `EVT-CBC-01-PLT-ADDENDUM`
- photo `2,60,904` → **downgraded to conflicting**, because another document supports the record value, so it is never asserted
- HER2 surgical `2+` → supports `EVT-HER2-SURGICAL`; outside biopsy `1+` → supports `EVT-HER2-OUTSIDE`; the two are linked `discordant_across_specimens`

Found on the way: PR #3's `reconcile_evidence` compared the two passes as raw strings. When it was run once on this account, it downgraded the photo reading because `"2,60,904"` ≠ `"2,60,904 /CUMM"`. That row was restored before the new version ran.
