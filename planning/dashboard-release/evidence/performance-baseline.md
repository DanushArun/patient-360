# Dashboard performance baseline

Checked 2026-10-02. These measurements cover the recorded `/design-preview`
fixtures for PAT-DC-04 and PAT-DC-09. They do not measure YJ28449, Snowflake,
authentication, network latency, or live patient-data performance.

## Method and environment

- Production Next.js build, BUILD_ID `y8nNHNFGxJflNPX0eyi_9`.
- Playwright 1.63.0 with Chromium 153.0.8010.12, Node.js 26.0.0, macOS 25.6,
  Apple Silicon (`arm64`), desktop viewport 1280×900.
- `npm run test:e2e`; the Playwright config launched the
  production server with Snowflake disabled. The server process had already
  passed its readiness probe before samples began.
- Each case has 20 samples. Fresh-context means a new browser context with an
  empty browser cache for each navigation; the server was warm. It is not a
  cold server-start measurement. Warm-document means repeated full document
  navigations in one context. Patient-switch and section timings measure the
  Playwright action through the expected visible state and include automation
  and protocol overhead; they are not INP measurements.
- LCP and CLS were recorded from browser PerformanceObservers on navigation.
  CLS uses the maximum session window (1 second gap, 5 second window); the
  browser reported both entry types. The JSON sample records are attached to
  the Playwright HTML report generated by the run.

All four cases passed. Times are milliseconds except CLS.

## Accepted local regression budgets

These budgets apply only to this same local fixture setup and desktop lab
environment. They are not production SLOs. Each p95 limit is enforced in the
Playwright suite with 20 complete finite samples per case.

| Scenario | Enforced p95 ceiling |
|---|---:|
| Fresh-context navigation with warm server | 300 ms |
| Warm full-document navigation | 150 ms |
| Warm roster patient switch | 150 ms |
| Patient-section interaction | 100 ms |
| Navigation LCP | 500 ms |
| Navigation CLS | 0.01 |

Google's published Core Web Vitals guidance sets good field thresholds at LCP
≤2.5 s, INP ≤200 ms, and CLS ≤0.1 at the 75th percentile, segmented by device.
Those are real-user field targets and cannot be established by these local
20-sample lab runs. This suite does not measure INP or mobile performance.
[web.dev: Web Vitals](https://web.dev/articles/vitals?hl=en)

## Verification record

The final full Playwright run passed 26/26 tests, including all four performance
cases with 20 finite samples per case. Every accepted p95 budget passed. The
maximum roster-switch sample was 115 ms and remains visible in the table. This
run used the production build above and recorded fixtures only. Detailed JSON
is preserved in `performance-raw/*-designer-final.json`; earlier enforced and
pre-enforcement samples are also retained. The first attempt against an
assumed already-running server failed with connection refused; successful runs
used the Playwright-managed production server.
